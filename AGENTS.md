# DrivingSupport contribution rules

Use these documents as the source of truth:

- Product: `docs/product/VISION.md`, `PRD.md`, `MVP_SCOPE.md`, `MVP_GAP_ANALYSIS.md`, `PRODUCT_STRATEGY.md`
- Delivery: `docs/roadmap/ROADMAP.md`, `MILESTONES.md`
- Process: `docs/process/GITHUB_WORKFLOW.md`, `DEFINITION_OF_DONE.md`, `PROJECT_FIELDS.md`
- Work logs: `docs/logs/README.md`

Rules:

1. Do not do direct feature work on `main`.
2. Every change requires a GitHub Issue.
3. Include the Issue ID in every branch name.
4. Stay within the Issue scope.
5. Do not invent requirements when source-of-truth documents answer them.
6. Run required verification before opening a PR.
7. Update documentation when behavior or architecture changes.
8. Create or update a work log for completed Issues.
9. Open a draft PR first.
10. Self-review the complete diff before requesting review.
11. Do not auto-merge.
12. Stop before merge and wait for project-owner GO.
13. Prefer small, independently reviewable Issues.
14. Preserve useful existing architecture unless evidence justifies change.
